# Проект 7: Первый автоматический цикл

Это переходный проект от «Harness» к «Loop». Вы уже знаете, как настроить агента с правильным окружением, инструкциями и обратной связью — теперь вы превратите эту настройку в цикл, который работает сам по себе. Вы проведёте три прогрессивных эксперимента: сначала превратите задачу из ручной в `/goal`, затем превратите задачу мониторинга в таймерный `/loop`, и наконец построите полный цикл maker-checker, чтобы почувствовать, каково это — **выйти из цикла.**

## Цель

Перейти от ручного управления к автономному циклу и на себе ощутить три фундамента из лекции о циклах: цель, метод верификации и условие остановки. К концу проекта вы должны уметь превращать повторяющуюся ручную задачу в цикл, который повторяется без вашего участия.

## Шаги

### Подготовка

1. Начните с того же коммита, на котором закончили Project 6.
2. Создайте три ветки: `p07-goal-loop`, `p07-timer-loop`, `p07-maker-checker`.
3. Подтвердите, что harness работает: запустите `init.sh`, проверьте файл состояния, список функций и документы передачи.
4. Выберите целевую задачу среднего размера с чёткими критериями завершения — например, «добавить модульные тесты до 80% покрытия».

### Эксперимент 1: целевой цикл

1. Напишите `goal.md`: чёткая цель, метод верификации, условие остановки и ограничения.
2. Выполните задачу вручную и запишите, сколько шагов и вмешательств потребовалось.
3. Запустите тот же `goal.md` в режиме `/goal` — агент циклится сам до достижения цели.
4. Сравните количество шагов, вмешательств и качество результата.

### Эксперимент 2: таймерный цикл

1. Выберите повторяющуюся задачу мониторинга (тесты каждый час, проверка зависимостей каждое утро).
2. Напишите скрипт/запрос мониторинга: что проверять, что делать при проблеме, когда звать человека.
3. Запустите с `/loop` на интервале 10–30 минут и дайте поработать минимум 2 часа.
4. Запишите: сколько проблем найдено, исправлено, сколько ложных срабатываний.

### Эксперимент 3: цикл maker-checker

1. Спроектируйте цикл: maker-агент (реализует), checker-агент (верифицирует), файл состояния `loop-state.md`, условие остановки.
2. Напишите три запроса: инструкции maker, инструкции checker, логика управления циклом.
3. Запустите минимум 5 раундов, записывая состояние каждого.
4. Проведите ретроспективу: сколько раз вмешались, где потолок качества цикла.

## Код

Пример файла состояния цикла:

```markdown
# Loop State

## Round 3
- Maker: added input validation to API endpoints
- Checker: 2 tests still failing on empty input
- Verification: fail
- Next: fix empty-input handling in validation layer
```

Шаблон условия остановки в `goal.md`:

```markdown
# Goal

## Objective
All unit tests pass with 80% coverage.

## Verification
npm test && npm run coverage

## Stop condition
Max 10 steps, or coverage >= 80% and all tests green.

## Constraints
Do not modify production config or database schema.
```

## Проверка

| Метрика | Цель (Эксп 1) | Таймер (Эксп 2) | Maker-Checker (Эксп 3) |
|--------|-------------|--------------|----------------------|
| Скорость завершения | Достигнута ли цель? | Сколько циклов отработало? | Сколько раундов до прохода? |
| Вмешательства | Сколько раз вмешались? | Время на сопровождение? | Сколько раз вмешались? |
| Качество | Сравнение с ручным? | Ложные срабатывания? | Проблемы, найденные checker'ом? |
| Надёжность | Доверительно ли условие остановки? | Убежал ли цикл? | Застревает ли на месте? |

Итог — понимание, какие задачи заслуживают циклизации, а какие нет, и где проходит граница вашего контроля.
