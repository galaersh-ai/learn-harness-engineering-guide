# Проект 6: Полный харнес (капстоун)

Это capstone-проект: соберите всё, чему научились в первых пяти проектах, проведите полный бенчмарк, затем сделайте проход уборки, чтобы убедиться, что качество поддерживаемое. Используйте фиксированный набор multi-feature задач, охватывающий полный продуктовый срез: импорт документов, индексация, Q&A с цитатами, runtime-наблюдаемость и читаемое перезапускаемое состояние репозитория.

## Цель

Собрать финальное, наблюдаемое, end-to-end агентское рабочее окружение и проверить, какие компоненты harness реально влияют на результат. Сначала запустите со слабым harness-baseline, затем с самым сильным harness, потом — уборку и повторный запуск, и наконец проведите эксперимент с абляцией: убирайте по одному компоненту за раз и смотрите, какие из них важны.

## Шаги

1. Возьмите почти готовый продукт с намеренно ослабленным harness из каталога `projects/project-06/starter/` (базовый `AGENTS.md`, без `feature_list.json`, `session-handoff.md`, clean-state checklist и benchmark/cleanup-скриптов).
2. **Baseline:** зафиксируйте ручные наблюдения со слабым harness.
3. **Полный harness:** соберите `solution/` со всеми компонентами (AGENTS.md, CLAUDE.md, feature_list.json, init.sh, session-handoff.md, clean-state-checklist.md, quality/evaluator-документы и скрипты).
4. Запустите `scripts/benchmark.sh` и `scripts/cleanup-scanner.sh`, затем сравните quality evidence.
5. **Абляция:** временно отключайте по одному компоненту и измеряйте влияние на результат.

## Код

Полная структура harness (каталог `solution/`):

```
solution/
├── AGENTS.md
├── CLAUDE.md
├── feature_list.json
├── init.sh
├── session-handoff.md
├── clean-state-checklist.md
├── docs/                # quality/evaluator-документы
└── scripts/
    ├── benchmark.sh     # полный прогон для замера качества
    └── cleanup-scanner.sh # поиск устаревших артефактов
```

Пример запуска бенчмарка:

```bash
#!/usr/bin/env bash
set -euo pipefail
npm test                 # полный прогон пайплайна
npm run lint             # линтер
./scripts/check-architecture.sh
```

## Проверка

- Какой процент функций перешёл в состояние `passing` при слабом и сильном harness?
- Что показал `cleanup-scanner.sh` — сколько устаревших артефактов?
- Какие компоненты абляции оказались критичными, а какие — лишними?

Итог — наблюдаемый, воспроизводимый harness с измеренным вкладом каждого компонента, а не набор «хороших практик» без доказательств.
