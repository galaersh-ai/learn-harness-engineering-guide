# Проект 4: Обратная связь и контроль scope

Добавьте runtime-наблюдаемость (логи запуска, логи импорта/индексации, состояния ошибок) и архитектурные ограничения, чтобы предотвратить нарушения границ слоёв. Затем подкиньте агенту runtime-баг для исправления. Вы запускаете задачу дважды: первый раз без логов и ограничений, второй — с правильными инструментами и правилами.

## Цель

Внедрить инструменты, позволяющие агенту тестировать свой код и исправлять ошибки во время выполнения, и ограничить его рамками архитектуры. Ключевой вопрос: помогают ли логи и проверки границ находить и чинить дефекты быстрее и аккуратнее.

## Шаги

1. Возьмите код Project 03 со слабыми диагностическими сигналами из каталога `projects/project-04/starter/`. Встроенный дефект indexing ломает чанкование больших файлов, а скрипта проверки архитектуры нет.
2. **Первый запуск:** дайте агенту runtime-баг без логов и ограничений. Зафиксируйте, как быстро он находит причину.
3. **Второй запуск:** добавьте структурированный логгер, документы архитектуры и скрипт проверки границ (`solution/`), затем снова дайте тот же баг.
4. Сравните скорость и аккуратность исправления в обоих запусках.

## Код

Ключевые файлы (каталог `solution/`):

```
solution/
├── src/services/logger.ts          # структурированный логгер
├── src/services/indexing-service.ts# исправленная логика чанкования
├── scripts/check-architecture.sh   # проверка границ слоёв
└── docs/ARCHITECTURE.md            # описание архитектурных границ
```

Пример структурированного логирования:

```typescript
logger.info("indexing:start", { file: path, size: bytes });
logger.error("indexing:chunk_failed", { file: path, reason: err.message });
```

## Проверка

- Как быстро агент находит корневую причину с runtime-сигналами и без них?
- Предотвратил ли скрипт `check-architecture.sh` нарушение границ слоёв?
- Исправление получилось точечным или затронуло несвязанные пути кода?

Итог — агент, который видит фактическое состояние среды выполнения и потому чинит настоящую причину, а не догадывается вслепую.
