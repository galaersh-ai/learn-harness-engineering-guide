# Проект 1: Только промпт vs правила

Соберите минимальный каркас Electron-приложения базы знаний — окно со списком документов слева, панелью Q&A справа и локальной директорией данных. Сама задача несложная; сложно — заставить агента её выполнить. Вы запускаете её дважды: первый раз только с промптом, без подготовки; второй раз — с уже размещёнными в репозитории `AGENTS.md`, `init.sh` и `feature_list.json`. Затем сравниваете, насколько велика разница.

## Цель

Почувствовать на практике, что правила «в первую очередь» (rules-first) дают по сравнению с голым промптом. Минимальный harness — это `AGENTS.md` + `init.sh` + `feature_list.json`; он превращает расплывчатую задачу в конкретную и проверяемую. Вы измеряете, сколько агент выполняет без дополнительной структуры и сколько — с ней.

## Шаги

1. Подготовьте стек проекта: Claude Code или Codex (выберите один и используйте для обоих запусков), Git, Node.js + Electron и таймер для фиксации длительности.
2. Возьмите проект из репозитория `projects/project-01/`. Четыре конкретные фичи: запуск окна, список документов, панель вопросов и ответов, создание локального каталога данных.
3. **Первый запуск (слабый harness):** используйте каталог `starter/`, где есть только `task-prompt.md` как описание задачи — без `AGENTS.md` и `feature_list.json`. Дайте агенту промпт и измерьте, что он выполнит.
4. **Второй запуск (минимальный harness):** используйте каталог `solution/` с явными артефактами: `AGENTS.md`, `CLAUDE.md`, `init.sh`, `feature_list.json`, `claude-progress.md`.
5. Сравните оба запуска по полноте выполнения, времени и количеству ваших вмешательств.

## Код

Минимальный набор harness-артефактов (каталог `solution/`):

```
solution/
├── AGENTS.md            # инструкции для агента
├── CLAUDE.md            # правила для Claude Code
├── init.sh              # фаза инициализации перед работой
├── feature_list.json    # список функций с ожидаемыми доказательствами
└── claude-progress.md   # журнал прогресса
```

Пример записи из `feature_list.json` — каждая функция описывается поведением, командой верификации и состоянием:

```json
{
  "id": "F01",
  "behavior": "App window opens with an empty document list on the left",
  "verification": "npm start && app window appears",
  "state": "not_started",
  "evidence": null
}
```

## Проверка

Смотрите `solution/feature_list.json` для ожидаемых доказательств по каждой из четырёх фич. Сравните два запуска:

- сколько функций агент довёл до реально работающего состояния;
- сколько раз он объявил «готово», когда проверка это не подтверждала;
- сколько времени занял каждый запуск и сколько раз вам пришлось вмешаться.

Ключевой вывод проекта — разница между «агент написал много кода» и «агент закрыл проверяемые функции по списку».
