# Проект 2: Рабочее пространство для агента

Добавьте «читаемость» в репозиторий, чтобы новый агент мог быстро понять структуру проекта, узнать текущий прогресс и продолжить работу с того места, где остановились. Конкретно: реализуйте импорт документов, просмотр деталей документа и локальное хранение, выполнив всё за две сессии. Вы запускаете задачу дважды: первый раз без какой-либо помощи, второй — с заранее размещёнными `ARCHITECTURE.md`, `PRODUCT.md` и `session-handoff.md`.

## Цель

Сделать репозиторий дружелюбным к ИИ и наладить механизмы передачи работы между сессиями. Репозиторий должен стать источником истины, из которого новый агент может восстановить контекст без повторного объяснения, — чтобы вторая сессия продолжала работу, а не открывала проект заново.

## Шаги

1. Возьмите код Project 01 (импорт документов, детальная страница и persistence ещё не завершены) из каталога `projects/project-02/starter/`.
2. **Первый запуск:** дайте задачу агенту без помощи. Зафиксируйте, сколько контекста второй сессии приходится открывать заново.
3. **Второй запуск:** разместите в репозитории `ARCHITECTURE.md`, `PRODUCT.md` и `session-handoff.md`, затем запустите две сессии подряд.
4. Сравните: может ли новая сессия продолжить работу только по состоянию репозитория.

## Код

Структура читаемого воркспейса (каталог `solution/`):

```
solution/
├── ARCHITECTURE.md      # как устроена кодовая база
├── PRODUCT.md           # что делает продукт и зачем
├── feature_list.json    # статус функций
└── session-handoff.md   # что сделано и что дальше
```

Пример `session-handoff.md` — состояние передаётся явно:

```markdown
# Session Handoff

## What was done
- Document import endpoint implemented (POST /import)
- Local storage directory created

## Current state
- Document detail view: in progress (rendering only)
- Persistence: not started

## Next steps
- Finish document detail view
- Add SQLite persistence for imported documents
```

## Проверка

- Может ли новая сессия агента продолжить работу, читая только `ARCHITECTURE.md`, `PRODUCT.md` и `session-handoff.md`, без ваших пояснений?
- Сколько времени уходит на «повторное открытие контекста» в каждом из двух запусков?
- Осталась ли вторая сессия на задаче, или ушла в сторону, переделывая уже готовое?

Итог проекта — измеримая разница между «агент тонет в незнакомом репозитории» и «агент сразу продолжает с места остановки».
